# FileFlow: как разобраться в проекте

FileFlow — приложение для Windows на C# и WinForms. Оно раскладывает файлы по категориям: документы, изображения, видео, аудио, архивы и установщики. Пользователь сначала видит план, затем выбирает файлы и подтверждает перемещение. Правила можно менять.

## 1. Начни с готового приложения

Распакуй переносную сборку и запусти `FileFlow.exe`. Нужен .NET 10 Desktop Runtime. На компьютере с .NET 10 SDK он уже может быть установлен.

Нажми **Try a sample folder**. Приложение создаст отдельную учебную папку. Файлы внутри — текстовые заглушки с разными расширениями: открывать их как настоящее видео или PDF не нужно.

В таблице будут шесть подходящих файлов и один пропущенный. Для `Meeting notes.txt` программа предложит `Documents\Meeting notes (1).txt`, потому что в Documents уже лежит одноимённый файл. Сними одну галочку и проверь, что число на кнопке изменилось. Верни галочку, выполни сортировку и нажми **Undo latest**.

Кнопки категорий над таблицей фильтруют список. Выбери **Documents**, затем **Move 2 files** и **Move files** в окне подтверждения: переместятся только отмеченные документы. Другие категории останутся на месте. **All files** вернёт весь список, а нажатие на заголовок **Size** отсортирует его по размеру в байтах.

## 2. Почему код разделён на два проекта

`src/FileFlow` отвечает за окно: кнопки, таблицу, диалоги и сообщения. `src/FileFlow.Core` знает о файлах и правилах, но ничего не знает о кнопках.

Поэтому логику можно проверить без ручного нажатия каждой кнопки. Если позже появится консольная версия, она сможет использовать те же `Planner` и `Organizer`.

`Program.cs` — точка входа. В ней настраивается WinForms и запускается `MainForm`. Атрибут `[STAThread]` нужен для корректной работы Windows-компонентов интерфейса, включая системные диалоги.

## 3. Как получается предпросмотр

Открой `Planner.cs` и найди `Preview`.

1. Проверяются правила и выбранная папка.
2. Правила превращаются в словарь: расширение → название папки.
3. Считываются только файлы непосредственно в выбранной папке.
4. Для каждого подходящего файла рассчитывается свободное имя назначения.
5. Создаётся `PlanItem` с исходным путём, назначением, размером и временем изменения.

На этом этапе папки не создаются, файлы не перемещаются. Результат — обычный объект `SortingPlan`.

`StringComparer.OrdinalIgnoreCase` позволяет одинаково обрабатывать `.jpg` и `.JPG`. `HashSet` запоминает имена, уже занятые другими строками плана. Это дополнение к проверке реально существующих файлов.

## 4. Зачем проверять файл ещё раз

Между предпросмотром и нажатием Move пользователь может отредактировать файл, а браузер — сохранить в папку новый документ. План становится устаревшим.

В `Organizer.Apply` повторно проверяются путь, размер, время изменения и доступность имени назначения. Если что-то изменилось, файл пропускается. Приложение не придумывает другое имя молча: пользователь должен увидеть новый план.

Размер и время — удобная, но не абсолютная проверка: если сторонняя программа специально сохранила прежнее время и прежний размер, изменение содержания может остаться незамеченным до перемещения. Для отмены используется более строгая проверка содержимого по SHA-256.

## 5. Почему журнал пишется до перемещения

Представь две команды:

```csharp
File.Move(source, destination);
SaveHistory();
```

Если приложение завершится между ними, файл уже перемещён, а записи об этом нет. Поэтому FileFlow сначала сохраняет запись со статусом `Prepared`, затем перемещает файл и меняет статус на `Moved`.

При следующей отмене программа смотрит, где находится файл, и сверяет SHA-256. Это помогает восстановиться после обычного прерывания операции. Журнал не заменяет резервную копию и не гарантирует сохранность при аппаратном сбое.

`JournalStore.Save` пишет JSON во временный файл, сбрасывает буфер на диск и заменяет основной файл журнала. Замена касается только собственного журнала программы. Пользовательские файлы перемещаются с `overwrite: false`.

## 6. Как работает отмена

`Undo` берёт последний незавершённый журнал и обходит записи в обратном порядке.

- Исходное место свободно, содержимое не изменилось — файл возвращается.
- На исходном месте появился другой файл — оба остаются на своих местах.
- После сортировки файл отредактировали — программа оставляет его там и сообщает об этом.
- Часть файлов восстановлена, часть пропущена — оставшиеся записи можно повторить через Undo.

Когда весь последний пакет отменён, можно отменить предыдущий. Пустые папки категорий остаются. Так программа не пытается удалять каталоги, в которых могли появиться чужие данные.

## 7. Как окно остаётся отзывчивым

Обработчики кнопок используют `async`/`await`. Работа с диском выполняется через `Task.Run`, а `Progress<T>` передаёт информацию в интерфейс.

Важная деталь: объект `Progress<T>` создаётся в UI-потоке до `Task.Run`. Тогда обновление надписей возвращается в правильный поток. Создание его внутри фоновой задачи было бы ошибкой.

Во время работы кнопки выбора папки и изменения правил недоступны. Отмена передаётся через `CancellationToken`. Она останавливает дальнейшую работу, но не откатывает уже выполненные перемещения автоматически: для этого есть Undo.

## 8. Как запустить проверки

Из папки проекта:

```powershell
dotnet build FileFlow.sln -c Release
dotnet run --project tests/FileFlow.Checks -c Release --no-build
dotnet run --project tests/FileFlow.UiChecks -c Release --no-build -- artifacts/ui
```

Первый набор создаёт временные файлы и проверяет 30 сценариев работы с диском. Второй открывает формы в отдельном тестовом процессе, использует учебные файлы и проверяет действия интерфейса. Он нажимает кнопки в настоящих окнах подтверждения, проверяет отмену, фильтры и сортировку, а затем сверяет расположение файлов на диске. Системный выбор папки нужно также попробовать вручную.

## 9. Как устроен собственный дизайн

В версии 0.2 интерфейс получил визуальный стиль **Stillwater**. Общие цвета, шрифт и скругления собраны в `Theme.cs`, а кнопки, карточки и контурные значки — в `FlowControls.cs`. Если поменять акцент в теме, он изменится сразу в нескольких окнах. Это основа, которую можно вынести в общую библиотеку для следующих приложений.

`Branding.cs` рисует логотип двумя кривыми и создаёт иконку Windows нескольких размеров. `FlowForm.cs` сохраняет системную рамку и кнопки окна; Windows 11 дополнительно получает цвет заголовка и скруглённые углы. `FileGridStyle.cs` оформляет таблицу, сохраняя стандартную модель выбора строк.

Размеры разметки заданы для 96 DPI. Windows увеличивает их при масштабе 125% и выше. В конце конструкторов форм явно устанавливается `AutoScaleDimensions = new SizeF(96, 96)`, после чего возобновляется разметка. Рисуемые вручную значки используют `DeviceDpi / 96f`. Без согласованной базы легко получить крупный шрифт внутри слишком маленькой кнопки.

Цвета помогают различать категории, но названия и статусы всегда написаны текстом. Кнопки сохраняют клавиатурный фокус. Подробнее о палитре и повторном использовании компонентов — в [дизайн-гайде](DESIGN.md).

## 10. Три небольших задания

1. Добавь в исходные правила папку Books для `.epub` и `.fb2`. Учти: сохранённые настройки пользователя не заменяются автоматически — нажми Restore defaults.
2. Найди, почему `.unknown` пропускается. Измени текст пояснения, не меняя поведения.
3. Добавь проверку, что правило для `.json` перемещает файл в Data и корректно отменяется. Используй `Fixture`, чтобы не трогать свои документы.

Сначала разберись с этими изменениями. Рекурсивная сортировка сложнее: в ней нужно исключать уже отсортированные папки и не заходить в ссылки и junctions.

## Что можно рассказать о проекте

«Я работаю над утилитой на C# и WinForms для сортировки файлов. В ней есть редактируемые правила, предпросмотр, обработка совпадающих имён и сохраняемая между запусками отмена. Логика отделена от интерфейса и проверяется на временных файлах».

Перед собеседованием пройди путь одного файла от `Planner.Preview` до `Organizer.Apply`, а затем объясни, почему запись `Prepared` сохраняется до `File.Move`. Это даст гораздо больше понимания, чем заучивание названий классов.
